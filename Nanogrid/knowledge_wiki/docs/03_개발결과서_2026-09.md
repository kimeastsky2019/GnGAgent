# NanoGrid 에너지 지식 순환 플랫폼 — 개발 결과서

> 작성일 2026-09-07 · GnG International · 대상 기간: 플랫폼 통합 착수 ~ 1차년도 착수
> 기준 배포본: https://nanogrid.gngmeta.com (빌드 스탬프 `build 2026-09-07 · 4tab+ESS`)
> 근거 기획: [기획서 v0.2](01_기획서_v0.2_지식플라이휠.md) · [3개년 연구개발계획 v1.0](02_3개년_연구개발계획_v1.0.md)

## 1. 요약

llmwiki(소스 분석 위키)와 nanogrid_AI_management_system(에너지 관제)을 하나의
**에너지 지식 순환 플랫폼**으로 통합하고, 기획 v0.2의 4탭 플라이휠
(**① 소스 코드 → ② 데이터 구축 → ③ 지식 데이터베이스 → ④ LLM 학습**)을
운영 서버에 구현·배포했다. 설계 원칙은 전 구간에서 **"사실은 SQL이, 서술은 LLM이"** 다 —
수치·사실은 항상 DB/파서 원천에서 오고, LLM은 그 위의 서술만 담당한다.

1차년도 착수 항목까지 가동 상태다: 학습 페어 적재 → 골든 승격 → CES 측정(주간 크론) →
L2 모델 교체 제안 → 인간 승인 → day-ahead 발행의 **전체 루프가 한 사이클 완결**되었다
(2026-09-07, 상세 §6).

## 2. 시스템 아키텍처

### 2.1 배포 구성 (nanogrid.gngmeta.com = 210.206.73.80)

```
[브라우저] ─ https ─▶ 호스트 nginx (JWT 로그인 게이트, /login·auth_request)
                        │ proxy
                        ▼
                 v2g_web :8000  (게이트웨이 nginx + 정적 프론트엔드 /srv)
                  ├─ /api/ng/*   ─▶ v2g_portal_api :8720  (ngwiki wiki-server)
                  ├─ /api/gov/*  ─▶ v2g_gov_api   :3001  (AI-Gov)
                  ├─ /api/wiki/* ─▶ v2g_llmwiki   :8722  (소스 분석 엔진)
                  └─ /(정적)     = apps/wiki 포털 (+ /nanogrid /gov /shell 서브앱)
     v2g_forecast :8801 (예측)   v2g_insight (인사이트 워커)   v2g_ingest (수집)
     v2g_db :5433 (TimescaleDB — ng.* 스키마 24 테이블)
```

- **캐시 정책**: HTML `Cache-Control: no-cache`, 해시 에셋 7일 캐시 —
  "배포했는데 화면이 안 바뀜" 문제의 구조적 해결. 사이드바에 **빌드 스탬프** 상설.
- **인증**: 서버측 JWT 게이트(nginx `auth_request` + auth 라우터). 비밀번호·API 키는
  서버 `.env`에만 존재하며 저장소·대화에 두지 않는다.
- **DB 안정화**: 재부팅 후 OOM 기동 실패(자동 튜닝 `shared_buffers` 12GB)를
  `shared_buffers=1GB` 명시 + `restart: unless-stopped`로 해결.
- **백업**: 일일 DB 덤프 크론(03:30) 가동.

## 3. 탭별 구현 결과

### ① 소스 코드 — 자기 소스를 스스로 분석한다

- LLMWiki 엔진을 `feature/nanogrid-portal`로 업그레이드: **프로젝트 등록 API**
  (`POST /api/projects` → 자동 파싱 → activate), 파이썬 파서(`python.py`·`pydata.py`),
  Java/XML 파서, 스캔 루트 격리(`server.browse_roots`, 컨테이너에 저장소를 읽기 전용 마운트).
- **실증**: 플랫폼 자신의 소스(v2g_nanogrid)를 등록해 **프로그램 25건 파싱,
  명세서 25건을 Grok으로 자동 생성** — "① 소스 코드" 탭에서 열람 가능.
  파서 산출(사실)과 LLM 서술의 분리 원칙 준수.

### ② 데이터 구축 — 모니터링·수요·태양광·V2G 플릿·ESS

- TimescaleDB `ng.*` 스키마 24 테이블: 계측(`measurements`), 예측(`forecasts`,
  `forecast_experiments`), 기기/충전기(`devices`, `ev_chargers`), API 등록
  (`api_registrations`), 학습(`training_pairs`, `golden_questions`, `ces_runs/scores`),
  승인(`approval_queue`), 규제(`gov_*`) 등.
- 수집: 시뮬레이터 상시 + **SP-G MQTT 수집기** 구현(게이트웨이 준비 시
  `SPG_MQTT_HOST` 설정만으로 실측 전환, 실측이 시뮬레이터를 UPSERT로 대체).
- 예측: forecast-svc — 모델 백테스트(`forecast_experiments`)와 day-ahead 발행.
- 대시보드: 모니터링 · 수요 관리 · 태양광 발전소 관리 · V2G 플릿(방전 스케줄/수익
  시뮬레이션/배터리 열화) · **ESS**(SoC/SoH/충방전, BMS·PCS API 등록) — 각 화면에
  데이터 소스 API 등록 UI 내장.

### ③ 지식 데이터베이스 — 지식 엔지니어링

- 인사이트 파이프라인: 일간·주간·이벤트 문서를 자동 발행. 모든 수치는 `facts_json`
  (SQL 원천)에 보존되어 서술과 대조 가능(KO/EN 병기).
- **자동화율 계기판**: 최근 7일 자동 처리 vs 인간 개입 비율을 지식 DB 화면에 상설
  (1차년도 A트랙 "계측 가능한 AI 직원 체제"의 증거 장치).
- 지식 검색(RAG-lite)과 위키 방법론·인사이트 문서 열람.

### ④ LLM 학습 — 페어 적재 · 골든셋 · CES · 승인 큐

- **학습 페어 파이프라인**: 챗봇 문답을 전건 `training_pairs`로 적재
  (`POST /learn/pairs` — 외부 UI도 사용 가능). 챗봇 화면에 **학습 승인 / 반려 /
  ★골든 승격** 버튼 — 승인분만 학습에 쓰이고, 골든 승격분은 학습에서 영구 제외
  (`human_approval='golden'` 오염 가드).
- **골든셋**: Claude 작성 시드 12문항 + 챗 승격분 = 현재 13문항 승인 상태.
  홀드아웃 원칙(학습 데이터 절대 편입 금지)을 스키마 수준에서 강제.
- **CES 측정**(`POST /learn/ces/run`): 심판 체인 Claude → Grok → 스텁.
  공식 CES는 Claude 심판만 인정(`official` 플래그), Grok 심판은 참고용으로 명시.
  채점 4축(정확성·근거성·완전성·안전성) 루브릭.
- **sLM 학습 대시보드**: 자동화율·CES 도넛, CES 실행 버튼, 골든/페어 카운트,
  승인 큐(승인/반려, L2 레벨 칩).
- LLM 공급자: 운영은 **Grok**(xAI, `XAI_API_KEY` 서버 .env 전용) — Claude는
  기준선·심판 역할로 예약(비용 정책). RAG 검색·AI-Gov(법률 업로드→분석→체크리스트,
  L1 사후 감사 큐 등록) 포함.

## 4. 자율성 등급(L0~L3) 구현 현황

| 등급 | 구현 | 상태 |
|---|---|---|
| L0 | 소스 파싱·데이터 수집·검색 | 상시 자동 |
| L1 | 인사이트 발행·명세서 생성·day-ahead 예측 → `approval_queue` 사후 감사 | 가동 (AI-Gov 분석도 큐 등록) |
| L2 | **예측 모델 교체 제안 루프**: 주간 백테스트 → 최적 모델 제안 → 승인 큐 → 인간 승인 시 교체·발행 | 가동 — 첫 사이클 완결 (§6) |
| L3 | 설비 제어·프로덕션 배포·규제 확정 | 인간 전담 (3차년도 부분 위임 실험 예정) |

**주간 자동화 크론** (KST 월요일 아침): CES 측정(08:05) · 모델 교체 제안(08:20) ·
일일 DB 백업(03:30).

## 5. 성과 지표 현황 (2026-09-07 기준)

## 6. 마일스톤 — 플라이휠 첫 사이클 완결 (2026-09-07)

1. 챗봇 문답 → 학습 페어 적재 → 골든 승격 (③→④)
2. 골든셋 13문항으로 CES 측정 — 0.662 (④)
3. 에이전트가 백테스트로 모델 교체 제안(L2): seasonal_naive(MAPE 18.97%) →
   hourly_profile(2.73%) (②→④)
4. **인간 승인** (승인 큐, decided_by 기록)
5. 시스템이 즉시 모델 교체 + 익일 day-ahead 96포인트 자동 발행 (④→②)

에이전트가 제안하고, 사람이 근거를 보고 승인하고, 시스템이 실행·기록하는
기획 v0.2의 핵심 루프가 운영 데이터로 증명되었다.

## 7. 주요 이슈와 해결

| 이슈 | 원인 | 해결 |
|---|---|---|
| DB 3일 다운 | VM RAM 축소(47→11GB) 후 자동 튜닝 `shared_buffers` 12GB로 OOM | `shared_buffers=1GB` 명시 + restart 정책 |
| CES 정확성 0점 | 챗 프롬프트가 "컨텍스트에 없으면 답변 불가"를 강제 → 개념 문항 전멸 | CES 전용 시스템 프롬프트(도메인 지식 허용) 분리 — 35.8%→60.4% |
| 배포해도 화면 불변 | index.html 무헤더 캐시 + 장기 오픈 탭(SPA) | no-cache 헤더 + 빌드 스탬프 + 해시 에셋 장기 캐시 |
| Grok 모델명 불일치 | 키별 허용 모델 목록과 컨테이너별 설정 상이 | 컨테이너별 모델 env 정리(llmwiki는 config 기본값 사용) |
| 로그인 한글 깨짐 | charset 미지정 | meta charset + nginx `charset utf-8` |
| 로컬↔서버 소스 불일치 | 서버 직접 패치 누적 | 서버→로컬 역동기화(10파일) + 이후 동기화 원칙 수립 |

## 8. 남은 과제 (즉시 실행 가능 순)

1. **공식 CES 전환** — 서버 `.env`에 `ANTHROPIC_API_KEY` 등록 (사용자 액션).
   등록 즉시 주간 크론이 Claude 심판으로 자동 전환.
2. **골든셋 확장** — 챗봇 ★골든 승격을 일상 운영에 편입, 100→500문항.
3. **SP-G 실계측 전환** — `SPG_MQTT_HOST` 설정 (크리티컬 패스, 게이트웨이 준비 시).
4. L2 제안 누적 관찰 — 승인율·수정률을 분기 감시 지표로.
5. training_pairs 승인 페어 축적 → 2차년도 SFT 준비.
