# NanoGrid AI System 개정 기획안 v0.2 — 스스로 개발하고 검증하는 에너지 AI 플랫폼

> v0.2 개정안 · 2026-09-07 · GnG International · 에너지 지식 순환 플랫폼
> 작성 기준: 배포본 nanogrid.gngmeta.com

소스 코드 → 데이터 → 지식 → 학습으로 이어지는 **닫힌 루프**를 에이전트가 돌리고,
사람은 **승인과 감사**만 수행한다. 3년 안에 사내 sLM이 에너지 도메인에서
**Claude 수준의 답변(CES ≥ 0.9)** 에 도달하는 것이 최종 목표다.

**v0.1 → v0.2 주요 변경**

- 선형 파이프라인 → **닫힌 루프(플라이휠)** 로 재정의 — ④학습의 산출물이 ①②③에 재투입
- 평가 체계 신설 — **Claude를 기준선·교사·심판으로 삼는 CES**(Claude 동등성 점수)
- 자동화 등급 L0~L3와 **인간 승인 필수 경계** 명문화
- "오늘의 로그가 내일의 학습 데이터" — 학습 데이터 파이프라인을 1년 차부터 가동
- 연차별 KPI·인프라(GPU/백업) 계획, 신뢰 사슬 UX 추가

## 1. 플랫폼 구조 — 4개 탭

각 탭은 독립 기능이 아니라 **루프의 한 단계**다. 탭마다 "무엇이 합격인가"를
기계가 판정할 수 있는 **합격 기준**을 갖는다. 기준이 없는 자동화는 하지 않는다.

| 탭 | 포함 기능 | 현재 자산 | 합격 기준 (기계 판정) |
|---|---|---|---|
| **① 소스 코드** (나노그리드 소스 분석) | 프로그램 명세서 자동 생성, 테이블·쿼리 분석, 규제 준수 체크 | llmwiki 소스 분석 (파서 + 문서 생성) | 사실 항목은 파서 산출과 100% 일치 · 명세서 커버리지 % |
| **② 데이터 구축** (모니터링 · 예측) | 실측 수집(SP-G/시뮬레이터), EV 충전기, 시계열 예측 랩 | ngwiki (TimescaleDB `ng.*`, forecast-svc) | 수요 예측 MAPE ≤ 10% · 24h 결측률 ≤ 2% |
| **③ 지식 데이터베이스** (LLMWiki · 지식 엔지니어링) | 인사이트 위키(일간·주간·이벤트), 진단 보고서 지식화, 검색 | insight 파이프라인 (facts_json 보존, KO/EN) | 모든 수치가 `facts_json`(SQL 원천)과 일치 · 근거 인용률 100% |
| **④ LLM 학습** (사내 AI) | RAG 검색, AI-Gov, 챗봇 시뮬레이터, sLM 학습 | rag_search_api, factgate, 사내 sLLM(qwen3:32b) | **CES**(§3) · 환각률 · 근거 인용률 |

## 2. 닫힌 루프 — 파이프라인이 아니라 플라이휠

①에서 파악한 코드로 개발하고, ②의 데이터로 검증하고, ③에서 **지식 엔지니어링**으로
지식화하고, ④에서 그 지식으로 sLM을 훈련한다. 여기까지는 v0.1과 같다.
v0.2의 핵심은 **되돌아가는 화살표**다: 훈련된 sLM이 ①의 명세서 작성, ③의 인사이트 서술,
②의 예측 해설에 재투입되고, 그 산출물이 다시 학습 데이터가 된다.
이 되먹임이 없으면 루프는 한 번 돌고 멈춘다.

```
 ① 소스 코드 ──(데이터로 검증)──▶ ② 데이터 구축
      ▲                                 │
 (코드 개선)     [인간 승인·감사]        │
      │          L3 GATE                ▼
 ③ 지식 DB ◀──(지식화)────────── ④ LLM 학습
      ▲                                 │
      └────── sLM 재투입 (점선 되먹임) ──┘
```

## 3. 평가 체계 — Claude가 기준선이다

사내 sLM의 목표는 **"에너지 도메인에서 Claude 수준의 답변"** 이다.
따라서 Claude를 세 가지 역할로 고정해 쓴다.

| 역할 | 내용 | 산출물 |
|---|---|---|
| **기준선** (Benchmark) | 동일 골든셋 질문에 대한 Claude의 답변을 만점 기준으로 삼는다 | 기준 답변 세트 (버전 고정·기록) |
| **교사** (Teacher) | Claude 답변을 정답 레이블로 증류(distillation) — 인간 승인을 거친 것만 SFT 데이터가 된다 | `training_pairs` (§5) |
| **심판** (Judge) | sLM 답변과 기준 답변을 블라인드로 비교 채점 (정확성·근거 인용·완결성·안전) | CES 리포트 (주간 자동) |

### CES — Claude 동등성 점수

**CES = (sLM 채점 합계) / (Claude 채점 합계)**, 같은 골든셋·같은 채점 기준에서.
1.0이면 동등, 0.9 이상이 3년 차 목표.

- **골든셋**: 탭별 평가 문항 — 소스 분석 Q&A, 운영 데이터 해석, 규제 판정, 예측 해설,
  현장 챗봇 질의. 사람 검수를 통과한 문항만 골든으로 편입. Y1 목표 500문항.
- **채점 축 4개**: 사실 정확성(SQL/파서 원천과 대조 가능해야 만점) · 근거 인용 · 완결성 ·
  안전(모르면 모른다고 답하는가).

**Claude-as-Judge의 함정 — 처음부터 통제한다**

- **자기 스타일 편향**: judge가 자기 문체를 선호할 수 있다 → 채점은 루브릭 점수제(축별 0~5),
  스타일 항목 제외, 블라인드·순서 무작위.
- **오염 금지**: 골든셋 문항은 학습 데이터에 절대 넣지 않는다(홀드아웃). 분기마다 신규 문항 20% 교체.
- **버전 고정**: 기준·심판 Claude 모델 버전을 기록하고, 버전 교체 시 전 골든셋 재채점으로 눈금을 다시 맞춘다.
- **인간 샘플링 감사**: 매주 채점 결과의 5%를 사람이 재검하고, judge와 사람의 불일치율을 별도 KPI로 추적한다.

## 4. 자동화 등급과 인간 승인 경계

원칙: **읽기·분석은 자동, 물리 세계와 프로덕션을 바꾸는 행위는 인간 승인.**
모든 에이전트 행위는 감사 로그에 남고, 배포는 원클릭 롤백이 가능해야 한다.

| 등급 | 행위 | 통제 | 예시 |
|---|---|---|---|
| **L0** | 읽기·분석·조회 | 완전 자동 | 소스 파싱, 데이터 수집, RAG 검색 |
| **L1** | 문서·예측 생성 | 자동 + 사후 샘플링 감사 | 인사이트 발행, 명세서 생성, day-ahead 예측 |
| **L2** | 코드 변경·모델 교체 | 자동 생성 → **인간 승인 후 반영** | 에이전트 PR, 예측 모델 스왑, sLM 체크포인트 승격 |
| **L3** | 설비 제어 · 프로덕션 배포 · 규제 판정 확정 | **인간 승인 필수** + 감사 로그 + 롤백 SLA | EV 충전/배터리 디스패치, 서버 배포, AI-Gov 최종 판정 |

**자기참조 문제의 해소** — 규제를 판정하는 AI-Gov 자신은 자동화 루프 밖에서
**분기별 인간 감사**를 받는다(판정 표본 재검 + 근거 인용 검증).
심판을 심판하는 자리는 항상 사람이다.

## 5. 학습 데이터 파이프라인 — 오늘의 로그가 내일의 학습 데이터

2년 차에 SFT를 하려면 1년 차부터 학습 가능한 포맷으로 로그를 남겨야 한다.
플랫폼의 모든 상호작용을 **instruction pair**로 적재하는 `ng.training_pairs` 테이블을 신설한다.

| 필드 | 내용 |
|---|---|
| `question / context` | 사용자·에이전트 질의와 근거(인사이트·SQL·조문 인용) |
| `answer` | Claude(교사) 또는 sLM의 답변 |
| `verdict` | judge 채점 (축별 점수) |
| `human_approval` | 승인/수정/반려 — **승인분만 학습에 사용** |
| `source_tab / model_ver` | 출처 탭, 생성 모델 버전 (재현성) |

수집원: 챗봇 시뮬레이터 대화, 인사이트 생성 요청/결과, AI-Gov 판정 로그, 소스 분석 Q&A,
예측 리포트 해설. 개인정보는 적재 전 마스킹(AI-Gov 체크리스트 준수).

**볼륨 목표**: Y1 승인 페어 1만 · Y2 10만(SP-G 실계측 전환 포함) · Y3 30만.
실계측 전환이 크리티컬 패스다 — 시뮬레이터 데이터만으로는 도메인 sLM이 현장 질문에 약하다.

## 6. 3개년 로드맵과 KPI

| | Y1 · 2027 「기반」 | Y2 · 2028 「증류」 | Y3 · 2029 「자율」 |
|---|---|---|---|
| **학습 전략** | RAG + 범용 sLM (지식DB가 곧 컨텍스트) | SFT/LoRA (Claude 증류 + 자체 승인 로그) | 도메인 sLM (에너지 특화 모델 상시 재학습) |
| **자동화** | L1 상시화 (문서·예측 자동 발행) | L2 가동 (에이전트 PR → 인간 승인 배포) | 루프 상시 자율 운전, 사람은 L3 승인 + 주간 감사 |
| **데이터** | 골든셋 500문항 · 로그 파이프라인 가동 · SP-G 실계측 전환 | 승인 페어 10만 · 멀티사이트 확장 | 사용자 테스트 자동화 (페르소나 테스트) |
| **CES** | ≥ 0.60 | ≥ 0.80 | **≥ 0.90** |
| **자동화율** | 40% | 70% | 90% |
| **인간 개입** | — | ≤ 20건/주 | ≤ 5건/주 |
| **운영 품질** | MAPE ≤ 10% · 결측 ≤ 2% | MAPE ≤ 8% | MAPE ≤ 7% · L3 사고 0 |

자동화율 = 전체 파이프라인 단계 중 인간 개입 없이 완결되는 단계 비율.
judge–인간 불일치율은 전 연차 공통 보조 KPI (< 10% 유지).

## 7. 인프라와 신뢰 사슬

### 인프라

- **GPU**: 현 클라우드 6090 1대(서빙) → Y2 학습 시 클라우드 버스트/임대 →
  Y3 온프렘 서빙(미니PC/신모델) 검토. 학습·서빙 분리.
- **백업/DR**: 단일 서버 SPOF 해소 — DB 일일 백업 + 오프사이트 보관, git 원격 미러 의무화,
  분기 복구 리허설. (최근 git 손상 1회·데모 DB 소실 2회의 재발 방지)
- **감사 로그**: 모든 에이전트 행위·승인·배포를 불변 로그로 — AI-Gov 감사와 CES 재현성의 토대.

### 신뢰 사슬 UX

4탭을 관통하는 **증거 링크**가 사용자에게 보여야 "믿을 수 있는 사내 AI"가 된다:
챗봇 답변 → 근거 인사이트 문서 → 원천 SQL 사실 → 소스 코드. 어느 화면에서든 한 번의
클릭으로 한 단계 아래 근거로 내려갈 수 있게 한다. 운영자·경영진·개발자 페르소나별
기본 화면은 Y2에 분리한다.
